# Промты страниц: веб-кабинет мультивалютного счёта (фиат + крипто)

Логика без брендов и стилей. Стек по умолчанию: **React + TypeScript**, SPA с боковым меню.

---

## 0. Общий контекст (вставлять перед каждым промтом)

```
Проект: личный кабинет мультивалютного счёта (фиат + крипто). SPA на React + TypeScript.
Layout: боковое меню (Dashboard, Deposit, Withdraw, Transfer, Convert, Verification,
Credit, Cards, About, Settings) + основная область. Мобильная версия: меню-бургер.

Доменная модель (TypeScript):
- Currency = FiatCurrency ('EUR'|'USD'|'GBP'|'CHF') | CryptoCurrency ('BTC'|'ETH'|'USDT'|'USDC')
- Account { id; currency; type: 'fiat'|'crypto'; balance: string /* decimal */ }
- Transaction { id; type: 'deposit'|'withdrawal'|'transfer'|'conversion'|'card_order'|'fee';
  method; currency; amount: string; status: 'pending'|'completed'|'rejected'; createdAt }
- User { id; firstName; lastName; email; phone; country; kycStatus: 'none'|'pending'|'approved'|'rejected';
  displayCurrency: FiatCurrency; avatarUrl? }

Правила:
- Деньги хранить как decimal-строки (decimal.js / big.js), не number. Крипто — 8 знаков, фиат — 2.
- Баланс = сумма проведённых записей леджера (double-entry), а не редактируемое поле.
- Все денежные операции создаются на бэкенде, идемпотентно (Idempotency-Key).
- Операции с деньгами недоступны, пока kycStatus !== 'approved'.
- API-слой через типизированный клиент (zod-схемы ответов), данные — через TanStack Query.
```

## 1. Dashboard (Главная)

```
Сделай страницу Dashboard.

Блоки:
1. Приветствие "Welcome back, {firstName}" + бейдж KYC-статуса.
2. Две карточки-сводки:
   - Total Fiat Balance — сумма всех фиат-счетов в displayCurrency.
   - Total Crypto Balance — сумма крипто-счетов в displayCurrency по текущему курсу.
3. Виджет банковской карты: общий баланс, эквивалент крипто, маскированный номер (**** 1234),
   держатель, срок действия. Клик — flip на обратную сторону. Кнопка выбора скина карты.
4. Быстрые действия: Deposit / Withdraw / Transfer (навигация на страницы).
5. CTA "Order Physical Card" — цена и срок доставки приходят с бэкенда; модалка подтверждения.
6. Accounts: табы Fiat | Crypto, список счетов (валюта, тип, баланс).
7. Recent Transactions: последние 10 операций (тип+метод, дата, сумма со знаком, статус-бейдж),
   ссылка "View all".

Логика:
- Конвертация в displayCurrency через хук useRates() (кэш 60 с).
- Скелетоны на загрузке, пустые состояния, обработка ошибок.
- Номер карты никогда не приходит на фронт целиком — только last4.
```

## 2. Deposit (Пополнение)

```
Сделай страницу Deposit.

Форма:
- CURRENCY: селектор, сгруппированный Fiat (EUR, USD, GBP, CHF) / Crypto (BTC, ETH, USDT, USDC).
- Для фиата — DEPOSIT METHOD: Bank Transfer | SEPA | Wire | Card.
  - Bank/SEPA/Wire: показать реквизиты для перевода (получены с API) + уникальный reference,
    поле AMOUNT, кнопка "I've sent the transfer" → создаёт pending-депозит.
  - Card: редирект на платёжный провайдер (Stripe Checkout и т.п.), фронт данные карты не видит.
- Для крипто — показать адрес депозита + QR + выбор сети, минимальную сумму и
  кол-во подтверждений. Зачисление — по вебхуку от кастодиана/ноды, не по кнопке пользователя.

Валидация (zod): amount > 0, лимиты min/max с бэкенда, точность по валюте.
После отправки — экран статуса и запись в истории со статусом pending.
```

## 3. Withdraw (Вывод)

```
Сделай страницу Withdraw.

- Сверху: доступный баланс Total Fiat / Total Crypto.
- CURRENCY: Fiat / Crypto группы.
- Fiat → WITHDRAWAL METHOD: SEPA | Wire | Card.
  Поля: имя/фамилия получателя (предзаполнить из профиля), IBAN/номер счёта (валидация IBAN
  с контрольной суммой), AMOUNT с кнопкой MAX.
- Crypto → адрес кошелька (валидация формата по сети), сеть, сумма, MAX.
- Показать комиссию и итоговую сумму к получению ДО подтверждения (рассчитывает бэкенд).
- Подтверждение через 2FA (TOTP / email-код).
- Сумма блокируется (hold) сразу, статус pending → completed/rejected; при rejected hold снимается.
- Ожидаемый срок обработки — текстом под формой.

Правила: amount <= available - fee; MAX учитывает комиссию; нельзя вывести при KYC != approved.
```

## 4. Transfer (Перевод)

```
Сделай страницу Transfer.

1. Выбор типа (карточки):
   - SEPA Transfer — EU/EEA, 0–1 день.
   - Wire Transfer — международный, 1–5 дней.
   - Card Transfer — на карту Visa/Mastercard.
2. Форма (зависит от типа):
   - CURRENCY (для SEPA — только EUR).
   - Sender: имя/фамилия (из профиля, read-only).
   - Recipient: Beneficiary name, IBAN, BIC/SWIFT (для Wire обязателен; + адрес банка и страна),
     Reference (optional, до 140 символов).
   - Card: номер карты получателя через токенизацию провайдера.
   - AMOUNT + MAX.
3. Шаг подтверждения: сводка, комиссия, курс (если валюта другая), 2FA.
4. Результат: статус + ссылка на транзакцию.

Валидация: IBAN (mod-97), BIC (8/11 символов), сохранение получателя в список "Saved beneficiaries".
```

## 5. Convert (Обмен валют)

```
Сделай страницу Convert.

- Переключатель режима: Fiat→Fiat | Fiat→Crypto | Crypto→Fiat | Crypto→Crypto.
- Поля YOU SEND (валюта + сумма) и YOU RECEIVE (валюта + расчётная сумма), кнопка swap.
- Курс: источник котировок (биржевой API), время последнего обновления, автообновление каждые 30 с.
- Двусторонний ввод: можно ввести сумму в любом поле, второе пересчитывается.
- "Convert Now" → бэкенд выдаёт quote с фиксированным курсом и TTL (например 15 с),
  с таймером; по истечении — перезапрос котировки.
- Показать спред/комиссию явно.

Правила: расчёт только на decimal; итог на бэкенде по quoteId, не по цифрам с фронта.
```

## 6. Verification (KYC)

```
Сделай страницу Verification.

Состояния по kycStatus:
- none: мастер из шагов — личные данные → документ (паспорт/ID, фото обеих сторон) →
  селфи/liveness → подтверждение адреса. Лучше интегрировать SDK провайдера (Sumsub/Onfido/Veriff).
- pending: экран "на проверке" + ожидаемый срок.
- rejected: причина отказа + кнопка повторной подачи.
- approved: "Verification Approved — full access".

Загрузка файлов: JPG/PNG/PDF, до 10 МБ, превью, прогресс. Файлы — в приватное хранилище
через presigned URL. Статус обновляется по вебхуку провайдера.
```

## 7. Credit (Заявка на кредит)

```
Сделай страницу Credit — мастер на 3 шага с прогрессом "Step N of 3".

Шаг 1 — Loan Details: сумма (EUR, min/max с бэкенда), цель кредита (select: Business,
  Real Estate, Vehicle, Education, Medical, Home Renovation, Debt Consolidation, Travel, Other),
  желаемый срок в месяцах.
Шаг 2 — Financial Info: занятость, ежемесячный доход, текущие обязательства.
Шаг 3 — Review & Submit: сводка, согласие с условиями, отправка.

Логика: состояние мастера в useReducer, валидация каждого шага (zod), черновик сохраняется.
После отправки — статус заявки (submitted/under_review/approved/declined) и список заявок.
Если показываешь примерный платёж — с явной ставкой и APR, помечено как предварительный расчёт.
```

## 8. Cards (Тарифы карт)

```
Сделай страницу Cards — выбор тарифа карты.

  список фич (дневной лимит, лимит ATM, поддержка, кэшбэк, доп. сервисы), бейдж "Popular".
- Текущий тариф пользователя помечен.
- Кнопка Select → модалка: сравнение с текущим, итоговая цена, источник оплаты, подтверждение.
- Ниже — 3 блока преимуществ (иконка + заголовок + текст).

Логика: оплата списывается одной транзакцией леджера; состояние кнопки (loading/disabled);
нельзя выбрать тариф ниже текущего, если это не предусмотрено.
```

## 10. Settings (Настройки)

```
Сделай страницу Settings.

Секции:
1. Profile Photo — загрузка аватара (JPG/PNG/WEBP, до 5 МБ), кроп, превью, fallback — инициалы.

   или с повторной верификацией).

Каждая секция — независимая форма со своим состоянием сохранения и toast-уведомлением.
```
